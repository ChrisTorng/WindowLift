# WindowLift

WindowLift keeps vertically oversized Windows dialogs usable. It adjusts only a window's vertical position and height; the horizontal position and width are never changed.

## Requirements

- Windows 10 or Windows 11
- [.NET 8 SDK](https://dotnet.microsoft.com/en-us/download/dotnet/8.0)

## Run

```powershell
dotnet run --project .\src\WindowLift.App
```

Alternatively, open the latest successful GitHub Actions **build** run, download the `WindowLift-win-x64` artifact, extract it, and run `WindowLift.exe`. The artifact is a self-contained 64-bit Windows build and does not require a separate .NET installation. It is not code-signed, so Windows may show an unrecognized-app warning.

Monitoring starts automatically. WindowLift scans existing windows once, then responds to native Windows show, foreground, and location-change events. Open, activate, or move an oversized dialog and it is handled immediately, including a reopened dialog with a new window handle.

## Options

### Allow over the taskbar

Uses the monitor's full height instead of the work area. When an adjusted window occupies taskbar space, WindowLift makes it topmost only while it has focus. The topmost state is removed immediately when focus moves to another window. A window that was already topmost is never demoted by WindowLift.

### Lift the title bar

When the window is taller than the normally available area, nearly one DPI-adjusted title-bar height may extend beyond the monitor's top edge. This preserves more content. The option does not cover a taskbar positioned at the top unless taskbar overlap is also enabled.

### Shrink the window height

Reduces an oversized window until its lower edge fits the selected boundary. The target application controls whether its layout adds a vertical scrollbar. Applications with a fixed-size or custom window implementation may reject the requested size.

The three options are evaluated together. For example, enabling both taskbar overlap and title-bar lift gives shrink-to-fit the largest permitted height; disabling both keeps the title bar visible and stops the lower edge above the taskbar.

## Safety and scope

- Only visible, non-minimized, non-maximized top-level windows with a title are considered.
- WindowLift never changes horizontal position or width.
- It does not activate target windows.
- A move generated by WindowLift is temporarily ignored by its own event listener.
- If Windows or an application rejects an off-screen position or size, WindowLift records the resulting bounds and does not retry until the window moves or an option changes. This prevents an unsupported window from bouncing or flickering.
- WindowLift runs without administrator privileges. Windows UIPI may block changes to an elevated application; run WindowLift at the same integrity level only when that application must be managed.

## Verify

Run the platform-independent placement smoke tests:

```powershell
dotnet run --project .\tests\WindowLift.Core.SmokeTests
```

Then test with an oversized dialog on Windows:

1. Start WindowLift and leave all three options enabled.
2. Activate the oversized dialog. It should react immediately, without a countdown.
3. Confirm its horizontal position and width remain unchanged.
4. Switch to another window and confirm the dialog is no longer topmost.
5. Close and reopen the dialog. The new instance should also be detected.
6. Toggle **Lift the title bar** and **Allow over the taskbar** to verify their respective top and bottom boundaries.
7. If the title is forced back on-screen by Windows or the application, confirm it remains stable rather than repeatedly jumping.
